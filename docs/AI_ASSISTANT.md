# AI Assistant

Open **Window > AI Assistant**. The panel docks beside Properties and can be
dragged into its own window. It operates the project currently open in Strata.
This integration uses the Python source installation; frozen builds are not
qualified and reject embedded-agent/MCP startup with an explanatory message.
No extra Python dependencies or model training are required.

## Connect an agent

Select **Codex** or **Claude Code**. Install the corresponding native CLI and sign
in using its own supported login flow (`codex login`, or run `claude`). Under
**Connection**, set the executable's full path if it is not on PATH. Windows
requires a native `.exe`, rather than a `.cmd`/`.bat` wrapper. Leave Model blank
to use the agent's default, or enter a model available to that account.

Type a request and press **Send**, for example:

> Inspect this project, add an editable rusty steel material, and check the result.

**Inspect view** asks the agent to inspect the live layer stack and request a
fresh render from the current 3D camera. Images are returned as MCP image content,
not filesystem paths. The capture does not include the chat panel or other apps.

The adapter uses the CLI's authentication; Strata neither copies login tokens nor
assumes a consumer subscription includes third-party use. Account eligibility,
provider terms, usage limits and billing remain with the provider. Codex uses
the local App Server's stdio protocol. Claude Code uses its noninteractive
stream-JSON interface and a Strata-only MCP configuration, with built-in tools
disabled. Codex runs in a dedicated project workspace with a read-only
sandbox and Strata operating instructions; existing global/managed Codex policy
still applies. This adapter is not a general sandbox for every provider tool.
Codex user-input/tool-permission questions appear in the panel; unsupported
shell/file approval interactions are declined and reported there.

Messages, requested project details and viewport images are sent to the selected
provider. The panel retains at most 100 messages locally, with bounded per-message
text and a 4 MiB serialized history limit. Older entries are discarded as needed.
History and provider session IDs live under `~/.strata/ai_history/`, keyed by the
project's persistent texture-set IDs. Portable save/reopen retains those IDs;
a newly created project starts a separate conversation. The agent service/CLI
can also retain its own conversation history according to its configuration.
Stable per-project working directories live under `~/.strata/ai_workspaces/`;
these keep CLI conversation resume independent of the source and asset folders.
**New chat** clears Strata's conversation and resume references for this project;
it does not delete provider-side history. History is separate from `.strata`
archives and is not included in portable delivery.

## Operations and recovery

The 15 exposed tools cover project inspection, documentation/catalog lookup,
viewport capture, layer creation/selection/material values, texture-set
selection, built-in smart materials, masks, selected native effects, deterministic
UV paths, native undo/redo, portable save and texture export. Their JSON schemas
are generated by `strata.ai_tools.specifications()` and checked before execution.
Tool metadata distinguishes read-only operations from edits and file output.

Layer edits use persistent IDs and native property validation/undo. The initial
interface exposes bounded material properties and a subset of brush/effect
parameters. `strata_guide(topic="catalog")` returns available presets and the
agent-supported effect parameter schemas. The broader engine documentation may
describe operations that have not yet been exposed as agent tools.

File output starts disabled when opening or switching projects. Enable **Allow saving
and export** when the agent should write files. A successful project save becomes
the desktop's current save destination. Other source import, project replacement,
arbitrary Python execution and automatic extension loading are not tool actions.

**Stop** disconnects the local bridge, terminates the embedded agent process tree,
and cancels queued operations. It also disconnects external agents using the
copied connection. Operations already completed remain in native history.
**Undo last edit** first stops the connection, then undoes one native operation.
A whole natural-language request can contain several undo steps; there is no
whole-request atomic rollback. Bake/render/native save operations already running
on the graphics thread finish before the UI can handle Stop.

The UI defers requests while an artist's property gesture, brush stroke, drag or
busy operation is active. Switching/closing projects revokes the old connection,
cancels its queue, and loads the corresponding local history. Agents should inspect
again at each new request; users can change the document between tool calls.

## External agents and other products

Under **Connection**, press **Copy external MCP connection**. Add that JSON to the
external agent's MCP server settings, using its documented configuration format.
The JSON contains the current interpreter, stdio adapter path and ephemeral
loopback connection credentials. Keep Strata open and treat the copied connection
as access to the open project. Stop, project changes and application exit revoke
it. Copy a new connection after reconnecting. Codex's TOML configuration requires
translating the same command, args and env fields into an `[mcp_servers.strata]`
table; it does not consume a Claude-style `mcpServers` JSON block directly.

The adapter can also be started as `python -m strata.ai_mcp`, with
`STRATA_BRIDGE_URL` and `STRATA_BRIDGE_TOKEN` supplied in its environment. It
implements MCP initialization, ping, tool discovery and tool calls over
newline-delimited stdio JSON-RPC. Guide/catalog content is exposed as a tool.
It is a deliberately small MCP implementation, without resources/subscriptions,
remote hosting, OAuth, or background MCP tasks.

Any product capable of running a local stdio MCP server can use these Strata
tools. An MCP connection does not embed that product's chat or reuse its account
inside Strata. Muse and other products require checking their supported interfaces;
there is no universal consumer-account connector. New embedded providers can be
added as streaming adapters in `ai_providers.py`, using the same Strata tool server.

## Implementation contract

- `ai_tools.py`: UI-independent tool schemas, checks, native engine dispatch and
  allowlisted documentation. No arbitrary evaluation or attribute dispatch.
- `ai_bridge.py`: authenticated `127.0.0.1` HTTP RPC with an ephemeral token,
  bounded request bodies/queue, denied browser-origin requests and cancellation.
  Only UI-thread `tick()` executes engine commands. Timed-out queued requests
  are cancelled rather than applied later.
- `ai_mcp.py`: stdlib-only stdio client of that bridge. No GPU/UI imports, proxy
  forwarding or HTTP redirects. Tool failures use MCP's `isError` result.
- `ai_providers.py`: native subprocess adapters, streamed messages, session resume,
  error reporting, hidden Windows processes and process-tree termination. Bridge
  credentials reach child processes through their environment, not command args.
- `ui/assistant.py`: docking UI, history, connection ownership, main-thread polling,
  fresh offscreen rendering and provider questions.

No project schema or renderer changes are required. Core engine and batch behavior
continue through the existing extension API. Documentation and live-session
qualification are recorded in IMPLEMENTATION_STATUS.md. Packaging support,
other-platform runtime and broader visual/artistic quality remain separate gates.

Provider protocol references: [Codex App Server](https://learn.chatgpt.com/docs/app-server),
[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp),
[Claude Code programmatic interface](https://code.claude.com/docs/en/headless).
